# AiPayWorlds — инструкция восстановления контекста

## Если ChatGPT потерял контекст проекта

Не пересказывай всю историю переписки.

### Шаг 1
Открой файл:

`docs/AI_CONTEXT.md`

### Шаг 2
Скопируй его содержимое и вставь в новый чат.

### Шаг 3
Вставь следующий текст:

> **ВОССТАНОВЛЕНИЕ КОНТЕКСТА AIPAYWORLDS**
>
> Перед тобой оперативный контекст проекта AiPayWorlds. Сначала восстанови контекст и ничего не меняй в проекте.
>
> 1. Прочитай переданный AI_CONTEXT.md.
> 2. Определи текущую фазу, цели, архитектуру, решения, риски и следующий шаг.
> 3. Составь список того, что восстановлено.
> 4. Составь список того, что устарело или требует проверки.
> 5. Найди возможные противоречия между AI_CONTEXT.md и текущими файлами проекта, если они доступны.
> 6. Не принимай новых архитектурных решений и не выполняй действий, пока восстановление не завершено.
> 7. Если данных недостаточно, прямо укажи, чего не хватает. Не выдумывай недостающий контекст.
>
> После восстановления ответь разделами: ВОССТАНОВЛЕНО / DRIFT / ПРОБЕЛЫ / РИСКИ / СЛЕДУЮЩИЙ ШАГ.

## Если AI_CONTEXT.md старый

Передай также:
- `PROJECT_STATE.md`;
- `DECISIONS.md`;
- `ARCHITECTURE.md`;
- `SECURITY.md`;
- нужные research/audit документы.

Если возможно, дай AI доступ к актуальному репозиторию, чтобы он сравнил документы с кодом и Git history.

## Если секрет попал в GitHub

НЕ ограничивайся удалением файла новым commit.

1. Сначала отзови/поверни секрет.
2. Затем оцени необходимость очистки Git history.
3. Проверь repository history и secret-scanning alerts.
4. Не публикуй секрет в чатах или issues.

## Что не надо передавать в публичный чат

Никогда не вставляй сюда:
- seed phrase;
- private key;
- API key;
- password;
- GitHub token;
- cloud credential;
- production signing secret.

Контекст проекта можно восстановить без этих данных.

## Частота обновления

Обновляй AI_CONTEXT.md:
- после каждого крупного milestone;
- после существенного архитектурного решения;
- после существенного security/research результата;
- перед важным deployment/release;
- минимум раз в неделю при активной разработке.

## Главное правило

`AI_CONTEXT.md` — это снимок текущего состояния, а не архив всей переписки.

GitHub project files + Git history являются более полным источником истины, чем память отдельной AI-модели.
