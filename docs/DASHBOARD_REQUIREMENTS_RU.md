# AiPayWorlds — требования к локальному Dashboard v0.2

Статус: зафиксировано до реализации.

## Главный принцип

Dashboard — локальное приложение для владельца проекта, рассчитанное на путь от полного новичка до самостоятельного разработчика. Пользователь не обязан знать программирование, Git, Linux или blockchain заранее.

**Ничего существенного не считаем само собой разумеющимся.** Перед реализацией каждой крупной функции создаётся спецификация: цель, пользовательский сценарий, данные, безопасность, ошибки, обучение, восстановление и тестирование.

## Язык

Интерфейс, подсказки, обучение, сообщения об ошибках, инструкции терминала, справочник и встроенная документация — на русском языке.

Технические идентификаторы (команды, пути, имена файлов, API/CLI flags, protocol terms) могут оставаться на английском, но рядом должно быть понятное русское объяснение.

## UX: «игра с развитием персонажа»

Dashboard должен ощущаться как единая среда развития проекта:

- стартовый уровень: «Новичок»;
- постепенное открытие сложных функций;
- уровни обучения и контрольные точки;
- прогресс по темам;
- понятные предупреждения;
- режим «объясни мне»;
- режим «покажи, что делать»;
- режим «профессионал» для более плотного интерфейса.

Нельзя искусственно блокировать знания. Продвинутый раздел можно открыть вручную.

## Memory Center

Память — центральная функция.

Dashboard должен показывать:

- текущий контекст проекта;
- последнюю синхронизацию;
- последнюю запись RUN;
- решения;
- открытые вопросы;
- изменения контекста;
- состояние локальной и Git-копии;
- историю восстановления.

Кнопки/действия:

- **Синхронизировать память**;
- **Создать snapshot**;
- **Создать пакет восстановления**;
- **Проверить целостность памяти**;
- **Показать изменения**;
- **Восстановить предыдущий snapshot** — только после подтверждения;
- **Экспортировать безопасный контекст**.

Пакет восстановления не должен содержать секреты.

## RUN Journal

Каждый значимый рабочий цикл получает RUN-ID. Dashboard автоматически показывает:

- цель;
- выполненные задачи;
- решения;
- изменённые файлы;
- результаты проверок;
- риски;
- следующие действия.

## AI Hub

Нужен отдельный раздел для AI-провайдеров. Архитектура должна быть расширяемой.

Планируемые режимы:

- ChatGPT через обычный веб-интерфейс;
- DeepSeek через обычный веб-интерфейс;
- дополнительные AI-провайдеры в будущем;
- локальные модели в будущем;
- API-провайдеры в будущем, если появятся ключи.

**Не требовать API key для режима обычного веб-интерфейса.**

AI Hub не должен хранить пароль, cookie, session token или API secret в проектных markdown-файлах. Авторизация выполняется самим пользователем в соответствующем защищённом веб-контексте.

Dashboard не должен выдавать себя за официальный клиент стороннего сервиса.

## Встроенный браузер

Желаемая функция: локальное окно браузера внутри приложения с вкладками.

Цели:

- не заставлять пользователя постоянно переключаться между окнами;
- открывать поисковик;
- открывать документацию;
- открывать GitHub;
- открывать ChatGPT;
- открывать DeepSeek;
- добавлять другие сервисы позже.

Важно: встроенный браузер **не является источником памяти проекта**. Он только интерфейс доступа к веб-сервисам.

Также предусмотреть возможность открыть страницу во внешнем Chromium.

## Терминал

Отдельный раздел «Терминал» должен использовать системный терминал Xubuntu, а не создавать второй несовместимый shell без необходимости.

Желаемый UX:

- встроенная терминальная панель;
- кнопка «Открыть системный терминал»;
- готовые команды для копирования;
- объяснение команды;
- уровень риска;
- ожидаемый результат;
- блок «если ошибка»;
- кнопка копирования;
- история выполненных playbook-шагов.

Опасные команды должны требовать явного подтверждения. Деструктивные действия не должны запускаться автоматически.

## Git Center

Показывать:

- текущую ветку;
- статус рабочей копии;
- последние commits;
- изменения;
- синхронизацию с GitHub;
- конфликт merge;
- кнопку безопасного snapshot/commit с предварительным просмотром.

Никаких автоматических force-push, reset --hard, удаления веток или переписывания истории без отдельного подтверждения.

## Learning Academy

Полностью локальная учебная база проекта.

Категории:

- Linux;
- Terminal;
- Git/GitHub;
- программирование;
- Python/TypeScript/Go/C++ — по необходимости проекта;
- blockchain;
- EVM;
- cryptography;
- smart contracts;
- security;
- DevOps;
- economics;
- tokenomics;
- business;
- research.

Каждый урок должен иметь: цель, объяснение простыми словами, пример, упражнение, проверку результата, следующий уровень.

## Графики

Dashboard должен показывать только полезные метрики, например:

- прогресс roadmap;
- выполненные RUN;
- технический долг;
- тесты;
- security findings;
- исследованные рынки;
- расходы проекта;
- funding pipeline;
- learning progress;
- состояние backup/memory.

Не добавлять графики только ради красоты.

## Offline-first

Ключевые функции должны работать без интернета:

- память;
- документация;
- учебные материалы;
- RUN Journal;
- roadmap;
- glossary;
- локальные файлы;
- backup/recovery;
- локальные git-операции.

Интернет нужен для внешних сервисов: GitHub sync, поиск, веб-браузер, ChatGPT, DeepSeek и актуальные исследования.

## Масштабирование

Архитектура Dashboard должна предусматривать модули/плагины:

- AI providers;
- browsers/search providers;
- Git providers;
- blockchain nodes/RPC;
- monitoring;
- backup providers;
- local models;
- future project modules.

Не привязывать ядро приложения к одному AI-провайдеру.

## Безопасность

Dashboard по умолчанию не имеет права:

- читать seed phrase;
- читать private keys;
- отправлять реальные деньги;
- публиковать mainnet transactions;
- удалять проект;
- менять Git history;
- удалять backup.

Если когда-нибудь потребуется опасное действие, оно должно иметь отдельный security gate и понятное описание последствий.

## Встроенное объяснение

Каждая сложная кнопка должна иметь:

- Что это?
- Зачем?
- Что произойдёт?
- Насколько это безопасно?
- Что ожидать?
- Что делать при ошибке?

## Контроль полноты

Перед реализацией Dashboard проводится отдельный Requirements Review. AI обязан искать пропущенные сценарии пользователя, ошибки, безопасность, восстановление, доступность, производительность, локализацию, обновление приложения и миграции данных.

Нельзя считать спецификацию полной только потому, что пользователь не назвал конкретную функцию.
